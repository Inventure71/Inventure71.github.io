Robot fleet control · 2025–2026

Mosaic

A ROS 2 fleet controller with an operator interface and movement control running on each robot.

  • Robotics systems engineering
  • Python · ROS 2 · UDP
  • Lab prototype
View repository ↗

Ownership

Control responsibilities

The supervisor handles coordination. Each robot reads its own sensors and OptiTrack pose, executes movement, and checks whether that pose is still current.

Robot agent
Owns path following, manual drive, stopping decisions, and the only local cmd_vel publisher.
Supervisor bridge
Translates UDP commands into ROS 2 actions and aggregates normalized robot state.
Operator tools
The Tk interface issues commands. Gama receives fleet state through a separate UDP export.

Interfaces

Shared topics and fleet configuration

Normalized ROS topics

Agents publish Mosaic status, pose, diagnostics, and path progress. The supervisor consumes these interfaces instead of depending on vendor-specific robot topics.

Shared fleet configuration

A common configuration defines robot namespaces, endpoints, and device roles. Launch packages and deployment scripts keep startup consistent across machines.

Lab validation

Physical validation requirements

Fleet membership is configured in advance. Physical validation depends on the robots, their ROS interfaces, OptiTrack, and the lab network.
