Fleet coordination

Control responsibilities

The supervisor handles coordination. Each robot reads its own sensors and OptiTrack pose, executes movement, and checks whether that pose is still current.

Robot agent
Owns path following, manual drive, stopping decisions, and the only local cmd_vel publisher.
Supervisor bridge
Translates UDP commands into ROS 2 actions and aggregates normalized robot state.
Operator tools
The Tk interface issues commands. Gama receives fleet state through a separate UDP export.

Interfaces

Shared topics and fleet configuration

Normalized ROS topics

Agents publish MOSAIC status, pose, diagnostics, and path progress. The supervisor consumes these interfaces instead of depending on vendor-specific robot topics.

Shared fleet configuration

A common configuration defines robot namespaces, endpoints, and device roles. Launch packages and deployment scripts keep startup consistent across machines.

Visualization & debugging

Put observations back into physical space

MOSAIC’s visualization component maps selected robot telemetry and independent tracking data onto a calibrated floor display. Source timestamps, units, coordinate frames, and provenance stay attached to observations; missing or stale evidence is shown as unavailable.

  1. ObserveRead selected robot telemetry and independent tracking data.
  2. CheckRetain the timestamp, coordinate frame, and validity of each observation.
  3. ProjectMap observations through shared calibration into the floor display.

Observation responsibilities

Inspect a run without commanding robots

Fleet control and visualization are components of the same project with separate responsibilities. The visualization hub owns calibration between tracking coordinates and the projection surface. Movement and stopping authority remain with each robot agent.

Independent evidence
External tracking and robot-reported reasoning remain distinguishable in the display.
Versioned recordings
Typed observations and metadata preserve the timing context of a debugging session.
Observation-only replay
Recorded evidence feeds the display and checks without sending movement commands to live robots.

Evolution

From Hydra to robot-local control

The linked public repository documents the earlier Hydra controller: a centralized ROS 1 backend and ROS 2 robot client. The current architecture described here moves path execution and stopping decisions into ROS 2 agents on each robot.

The public repository is historical source for the fleet controller’s evolution. The visualization and replay component is described separately in the visualization & debugging detail.

Lab validation

Physical validation requirements

Fleet membership is configured in advance. Validating movement depends on the robots, their ROS interfaces, OptiTrack, and the lab network. The visualization component also requires projector alignment, tracking calibration, and checks on the lab hardware.
