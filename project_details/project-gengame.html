A multiplayer battle arena where you don't just pick a loadout — you describe a new mechanic in plain English, and an AI writes it, tests it, and merges it into the match. Everyone's ideas get stitched into a build that exists for that one game only. Also, you're a cow.

The short version

Core Conflict is a battle royale where the game itself is editable mid-lobby. Players request features in English; a multi-agent pipeline writes and tests the code, then a git-like patch system merges everyone's picks into a single, one-off match.

  • Every generated feature has to pass pytest before it's allowed in — fail, and the agent enters a fix loop.
  • A decentralized patch system merges each player's features, with the LLM resolving genuine code conflicts.

How the magic works

English in, playable code out

  • Describe it in English

    Type what you want — a new ability, a balance tweak — and the agent reads the actual game code and writes Python that plugs straight into it.

  • Tested before it ships

    Nothing reaches the match untested. Generated code runs through pytest, and if it fails the agent loops on fixing it until it's green.

  • Everyone's build is different

    On game start the server gathers each player's chosen patches and merges them — caching, deterministic rules, and the LLM for real conflicts — into a match that exists exactly once.

The game is its own developer

Most games freeze their rules at launch. Core Conflict turns the developer loop into a runtime loop: it writes, tests, and ships its own code while you're still in the lobby. It's an ambitious, occasionally-held-together-with-tape prototype — but the first time a stranger's half-baked idea and yours both land in the same match, it genuinely feels like magic. (And yes, the abilities are all cow puns.)

The evolution cycle

How a patch is born

01

Request

A player describes the mechanic they want, in plain English, from the lobby.

02

Build & test

A chain of specialized agents — planner, coder, tester — writes the Python and runs it through pytest, fixing until it passes.

03

Merge

At game start the server collects every player's patches and merges them, calling the LLM only for the conflicts it can't resolve on its own.

04

Hot-reload

The unified build syncs to every client and loads in — one match, everyone's ideas, running live.
