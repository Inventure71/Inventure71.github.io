Hand-built algorithms

The queue, linked list, and pathfinder are written from scratch, with time and space complexity documented alongside them. A greedy opponent scores threats and chooses counters.

  • Big-O on everything: nearly every function documents its time and space complexity.
  • Size-aware BFS: pathfinding that validates a troop's whole footprint, not just one cell.
  • Opponent logic: greedy threat scoring with a hard-coded counter table.

Algorithms in the game

BFS Pathfinding

Lives in arena/utils/find_path_bfs.py. Every troop finds its route on the arena grid — and the search checks the troop's full width and height, so big units don't clip through gaps they can't fit.

  • Time: O(V + E) · Space: O(V)
  • Path is rebuilt with a hand-written stack — no recursion to overflow.

Merge Sort

A custom merge_sort_by_key in core/sorting.py orders troops by their position on screen so they draw in the right front-to-back order.

  • Time: O(n log n) · Space: O(n)
  • Stable, so ties keep their original order.

Custom queue & linked list

The BFS frontier and path use structures I wrote from scratch — a queue with a tail pointer and a linked list — instead of reaching for collections.deque.

  • Enqueue / dequeue: O(1)
  • The implementation documents its complexity and compares it with an array-backed approach.
