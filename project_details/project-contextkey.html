Experimental macOS prototype

ContextKey

macOS has no universal "what am I typing" API, so nobody's shipped a system-wide autocomplete that respects your privacy. ContextKey is my attempt — it reads the field you're in, asks a model running on your own Mac for a short continuation, and offers it inline. No text ever leaves the machine.

Context, without leaving the app you're in

It reads the text surface you're focused on, stitches together the context around it, asks a local model for a short continuation, ranks what comes back, and draws it right next to your cursor — all without you switching windows.

  • Accessibility APIs and optional Vision OCR cover native apps; a tiny browser extension feeds in structured DOM context.
  • The model runs on the Mac via MLX, and a global event tap accepts the suggestion — never hijacking the editor you're already using.

Prototype pipeline

Capture, generate, filter, overlay

01

Capture

Grab the focused field, the text around it, which app I'm in, and any structure the browser can hand over.

02

Generate

Hand a compact prompt to a language model running locally through MLX.

03

Rank

Throw out anything low-quality, unsafe, repetitive, or poorly grounded — which, most of the time, means suggesting nothing.

04

Overlay

Draw a faint inline suggestion, and only insert it when you actually accept with Option-Space.

The hard part was teaching it to stay quiet

Most of the engineering here isn't generating text — it's refusing to. A suggestion that says nothing when it's unsure feels far smarter than one that confidently guesses wrong, so the ranker discards anything that just repeats what you typed, narrates itself, or looks unsafe. It's still a research prototype — the context capture and localhost transport need a stricter security model before I'd trust it in production — but that restraint is the part I'm proud of.
