The cursor crosses because the systems agree

Project Unity is not screen sharing. Native apps on both computers negotiate who owns input, map their displays in physical space, and move mouse, keyboard, wheel, gesture, and media-key state over a private LAN.

  • Six-digit pairing creates stable device identities; ownership and realtime traffic are authenticated and encrypted.
  • Control works in both directions, with explicit leases and watchdogs that restore local input when the path fails.

System boundaries

Discovery, ownership, input

Find and trust

DNS-SD discovers peers, manual addressing provides a verified fallback, and concurrent six-digit confirmation prevents pairing with the wrong machine.

Own and transport

An authenticated TCP lease decides who controls what. Encrypted UDP carries cumulative motion and complete button/key snapshots without turning one lost packet into a stall.

Capture and recover

Native event capture feeds macOS posting or Windows SendInput. Sequence tracking, transition journals, fail-safe release, and ACK watchdogs make failure return control locally.

A convincing MVP, not a release claim

The paired Mac–Windows path is working and instrumented, but the protocol still needs independent security review, the Windows binaries need Authenticode signing, and a true three-device physical matrix remains open. Software timing also cannot replace motion-to-photon testing in a real target application.
