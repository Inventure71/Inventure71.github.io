PaddockJS

This whole site presents my projects as Formula 1 cars on a grid — PaddockJS is the engine that makes them race. It started as that portfolio toy and grew into a real npm package: a PixiJS renderer for the browser, with a deterministic headless environment underneath.

A package, not a one-off animation

PaddockJS owns the entire simulation — renderer, assets, race runtime, mount APIs, data contracts, and rules. A host site just hands it project data and decides where things go. It even grew a Gym-style headless environment, so you can train a driving model on the exact physics you watch in the browser.

  • One controller drives both the all-in-one race and individually placed surfaces — timing tower, telemetry, controls.
  • A CSS-free headless subpath steps the same deterministic sim, with no PixiJS and no browser.

System boundaries

One simulation, several ways to use it

Drop-in race

One call puts a full race into a page — cars, track, timing tower, telemetry — with loading and failure handling already wired up.

Composable surfaces

Or scatter the controls, canvas, timing, and telemetry across your own layout, all sharing a single simulator behind them.

Headless environment

Training code steps the identical deterministic sim through a Gym-style reset/step API — no rendering, no CSS, fully reproducible from a seed.

And then it actually learned to drive

What began as a UI toy turned into a genuine reinforcement-learning playground. I cloned the sim's built-in AI into a small PyTorch network, repaired its failure cases with DAgger, and picked the best three-model committee by real driving score across 80+ procedurally generated tracks it had never seen. It now races right here in the browser with zero ML dependencies — the whole "brain" is just JSON weights run through a tanh MLP.
