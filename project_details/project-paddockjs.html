Use a complete race view or place the track, controls, timing, and telemetry separately. A headless API runs the same simulation for experiments and training.

System boundaries

One simulation, several ways to use it

Drop-in race

One call puts a full race into a page — cars, track, timing tower, telemetry — with loading and failure handling already wired up.

Separate components

Place controls, canvas, timing, and telemetry in your own layout, connected to a shared simulator.

Headless environment

Training code steps the identical deterministic sim through a Gym-style reset/step API — no rendering, no CSS, fully reproducible from a seed.

Testing custom drivers

The headless environment exposes observations, actions, and repeatable scenarios for testing driving policies. A custom controller can also run in browser playback, where you can inspect its braking, track limits, and recovery.
