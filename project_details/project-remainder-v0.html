Two related prototypes

ReminderZ organizes messages. Project Loom provides a visual programming editor; the two share a development environment.

  • ReminderZ: a desktop app that pulls in my Telegram/WhatsApp notes-to-self and uses Gemini to sort them into projects and reminders.
  • Project Loom: a later, separate tool — a node editor that compiles a visual block graph into runnable Python, with a local RAG engine.
  • Loom uses ReminderZ’s conda environment.

ReminderZ

Organize messages and reminders

ReminderZ imports notes sent through Telegram and WhatsApp. Gemini groups them into projects and proposes reminders with dates and importance scores. Answers to questions reference the source messages.

  • Auto-organizing

    Batches of unprocessed messages go to Gemini, which files each into a project — or invents a new project when a cluster of loose notes calls for one.

  • Reminders it infers

    For every message it decides whether it's a reminder, sets a time, and rates importance 1–10 — no manual tagging.

  • Answers with sources

    Chat over your messages and it cites the exact message IDs behind its answer, like [1,14,33].

Project Loom

Building programs by wiring blocks

A blueprint-style editor

An infinite canvas of typed blocks — Executor, Function, Variable, Conditional, Operator — where exec pins flow one way and value pins fan out.

  • A graph-walker compiles it into real Python, starting from BeginPlay.
  • It scans your modules to auto-generate function blocks.

Draw your UI

Sketch shapes on a canvas and Loom recognizes them — rectangles become buttons and inputs, circles become toggles — then emits the matching UI code.

  • Simple aspect-ratio rules decide what each shape turns into.

Local semantic search

A FAISS index and local EmbeddingGemma embeddings provide offline semantic retrieval without generating an answer.

  • Add, replace, and delete documents with a persistent id map.

Electron on top of Python

The renderer is Electron and vanilla JS; the compile-and-run backend is Python, spawned through the shared conda environment.

  • An optional debugpy server hooks into the generated code.

How they relate

Project Loom grew from the ReminderZ codebase and shares its Python environment. They remain separate prototypes with different interfaces and workflows.

Under the hood

The pieces on each side

Message ingestion · ReminderZ

A Telegram bot fetcher (offline-safe, saves attachments) and a WhatsApp Web scraper feed messages into SQLite.

Gemini organizer · ReminderZ

Batches messages to Gemini 2.5 Flash with JSON schemas for three tasks: assign projects, extract reminders, and invent new projects.

Local store · ReminderZ

Messages and projects persist in SQLite, each row tracking content, project, reminder time, importance, and done state.

Node editor · Loom

An infinite canvas of typed blocks, described by a JSON contract of pins and connections.

Python code-gen · Loom

A graph-walker turns the block graph into Python, generating stub modules on the fly from BeginPlay outward.

Local RAG · Loom

FAISS + Ollama EmbeddingGemma for offline semantic search, with a persistent index and an id map for add/replace/delete.

Flow · ReminderZ

How a message becomes structure

01

Capture

Your Telegram and WhatsApp messages get pulled in and land in a local database.

02

Batch

Unprocessed messages are grouped and sent to Gemini in schema-constrained chunks.

03

Organize

Gemini files each message into a project, flags reminders with a time and importance, and spins up new projects when needed.

04

Recall

Ask a question later and it answers straight from your messages, citing the ones it leaned on.

Status

Prototype status

  • Both are prototypes with limited automated test coverage.
  • ReminderZ ingests and organizes messages; its token counting uses a placeholder rather than Gemini’s tokenizer.
  • Project Loom compiles simple graphs to Python and supports local semantic retrieval.
  • The prototypes share an environment but are not integrated into one application.
